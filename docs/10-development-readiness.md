# 10 – Development Readiness

## Obiettivo della fase

Verificare che uno use case sia pronto per entrare in sviluppo, evitando POC o MVP senza governance, valore e rischio minimi.

| Controllo | Descrizione | Stato |
| --- | --- | --- |
| Business Sponsor | Identificato e ingaggiato. | OK / KO |
| Product Owner | Identificato. | OK / KO |
| IT Owner | Identificato. | OK / KO |
| KPI principale | Definito. | OK / KO |
| Baseline | Disponibile o pianificata. | OK / KO |
| Target | Definito. | OK / KO |
| Formula economica | Definita. | OK / KO |
| Decision Rights | Completati. | OK / KO |
| AI Risk Gate | Completato. | OK / KO |
| Data Readiness | Validata con IT. | OK / KO |
| Next Step | POC / MVP / Pilot definito. | OK / KO |

**Regola:** se un elemento obbligatorio manca, lo use case resta in HOLD, Deep Dive, Data Assessment o Business Validation.

## Nota

La Development Readiness non dispone di un foglio dedicato nel Calculator. Rappresenta una checklist trasversale che verifica che Value Realization, AI Risk Gate e Governance & Controls siano stati completati correttamente.
